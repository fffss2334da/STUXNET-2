# Stuxnet: локальные функции и стабильность

Этот список собран из всех требований в переписке. Fake-данные ниже означают локальные проекции приложения: они не меняют Telegram-сервер и не должны уходить в API.

## Чаты и сообщения

- [x] Fake-сообщение хранится локально и сразу добавляется в Postbox, без сетевого поиска отправителя.
- [x] Дата нового fake-сообщения по умолчанию равна текущему времени; ручной выбор даты остаётся дополнительной возможностью.
- [x] Локальный chat list включает подходящий личный чат и использует обычную историю Telegram для перехода в диалог.
- [x] Исправить переход из шапки подарка к отправителю: сначала закрыть модальное окно, затем открыть чат.
- [x] Исправлены повторный вход и возврат из preview-чата, а также закрытие preview overlay перед профилем и форумом.
- [x] Fake-сообщения и fake-подарки проецируются в Postbox и включают peer в chat list сразу после записи.
- [x] Удаление через меню чата, fake-редактор и «удалить все» очищает Postbox, локальную историю и связанные локальные Stars-события; очистка повторно безопасна.
- [x] Редактирование сохраняет стабильный id, точное время и порядок истории; атомарные projection/update paths убирают задержки и дубли.
- [x] Удалённые сообщения и чаты получают отдельную локальную отметку/настройку отображения, не меняя сообщения Telegram на сервере.
- [x] Сохранена совместимость старых локальных записей, journal recovery после неполной записи и пакетное добавление больших скриптов.
- [x] Fake-переписки поддерживают строки «от меня/от собеседника», медиа, дату, Stars-сумму и понятный preview.

## Локальные каналы и профиль

- [x] Начать отдельную versioned модель fake-канала, независимую от `TelegramChannel` и сетевых API.
- [x] Доведён канал-конструктор: несколько каналов, аватар из медиатеки, описание, public/private, локальный username/link, подписчики и Stars.
- [x] Есть локальные роли owner/admin/member, отдельные tag/role label/owner identity, кнопки редактирования и удаления.
- [x] Локальные посты поддерживают текст, медиа из медиатеки, дату, просмотры, комментарии, Stars, реакции и Stars-реакции.
- [x] Посты открываются в Telegram-похожем локальном интерфейсе; owner/admin получают встроенную строку публикации, member видит режим без прав.
- [x] Добавить локальную модель username, телефона и имени профиля без изменения аккаунта на сервере.
- [x] Account-local и per-peer overrides: username/tag, номер, имя и локальная подпись owner/admin; проекция подключена к списку чатов, заголовку и профилю.
- [x] Реальные разрешения и контакты не подменяются сетевыми значениями; локальные override остаются отдельным слоем отображения.

## Подарки и NFT

- [x] Хранить fake gifts локально; привязывать gift-проекцию к чату и профилю без отправки подарка в Telegram.
- [x] При локальном transfer хранить нового owner и показывать статус передачи.
- [x] Preview подарка/NFT использует штатные GiftView/GiftItem renderers и серверный snapshot model/backdrop/pattern/3D paths.
- [x] `Gifted by` показывается только когда отправитель присутствует в серверном gift snapshot/originalInfo; отсутствие подписи не заполняется искусственно.
- [x] `Sent this gift to you` находится внутри конкретного gift action bubble, а не общей подписью чата.
- [x] После локальной отправки/transfer согласованы sender, recipient, новый владелец, chat action, профиль и ledger; повторный transfer идемпотентен.
- [x] Конвертация в Stars обновляет баланс, профильную проекцию и журнал ровно один раз.
- [x] Transfer fee по умолчанию соответствует Telegram-логике (25 Stars для соответствующего NFT), учитывает snapshot/настройку и отображается в подтверждении/истории.
- [x] Исходный локальный подарок удаляется только после успешной записи результата; повторный запуск привязан к сохранённому recipient intent.

## Stars, реакции и статистика

- [x] Есть account-local Stars ledger с балансом, журналом, пополнением, списанием и событиями conversion/transfer.
- [x] Исходящее fake Stars-сообщение списывает баланс, входящее начисляет; редактирование применяет разницу.
- [x] Удаление fake Stars-сообщения идемпотентно компенсирует баланс и оставляет запись об удалении.
- [x] Баланс fake Stars обновляется после пополнения, conversion, transfer, channel post и fake Stars-сообщения.
- [x] Stars отображаются в stats и смешиваются с Telegram transaction history с локальным источником операции.
- [x] Fake-посты каналов поддерживают Stars на пост, Stars-реакции, количество/значение реакций и локальный баланс канала.
- [x] Fake-переписка позволяет выбрать входящее/исходящее количество Stars, показывает «отправлено за N Stars» и записывает событие в ledger/history.
- [x] Рейтинг вычисляется из локального значения Stars и отображается заполненным в Stuxnet-проекции.

## Ghost mode, медиа и визуал

- [x] Ghost Mode имеет понятные глобальные, account и peer настройки для read receipts, online, typing/story packet controls и перезапуска.
- [x] Для собственного профиля используется server-authoritative серверная метка `wasOnline`; профиль показывает абсолютное время последнего входа, без `Last Seen · Just now` и без локальной временной подстановки. Отдельный переключатель в обычных настройках удалён, поле codec оставлено для чтения старых настроек.
- [x] Поддерживаемая ссылка на видео отправляет видео прямо в текущий чат с процентом, отменой и повтором; Files/Photos не используются автоматически.
- [x] Подбор медиа для фото/видео/файлов/voice идёт через медиатеку; локальные ресурсы валидируются до вставки.
- [x] Voice changer подключён к voice message/trimmed audio и realtime call paths; preset picker сохраняет состояние.
- [x] Picker шрифтов показывает живой пример выбранного UIFont с fallback и кириллицей.
- [x] Улучшен внешний вид подарков, удалённых сообщений и общая визуальная гибкость без сетевой подмены данных.
- [x] Заменены Stuxnet app/alternate icon assets во всех iPhone/iPad размерах на отдельный circuit-loop знак.

## Архитектура и выпуск

- [x] Хранить сообщения, gifts, Stars и каналы в локальных моделях, отделённых от сетевого API.
- [x] Зафиксирована схема версий для каналов, профилей, gifts, Stars ledger и fake-message snapshot; старые массивы мигрируют, неизвестная версия открывается read-only там, где запись опасна.
- [x] Локальные модели отделены от сетевого API; Telegram-specific gift/profile projection собран в узких adapters.
- [x] Очереди публикации, Postbox-операции, атомарная запись, очистка и пакетные наборы защищены от дублей и повторного запуска.
- [x] Regression tests для stores/ledger/settings добавлены в workflow перед production build; macOS-only execution остаётся CI-проверкой.
- [ ] После завершения функциональных пунктов запустить полный `build-stuxnet.yml`, исправить ошибки, проверить IPA/dSYMs и приложенный artifact.

## Повторная проверка перед выпуском

Эти проверки выполняются после каждого связанного изменения и отмечаются только
после проверки фактического пути, а не только наличия модели или экрана.

- [x] Собственный профиль: серверное presence отображается при включённом Ghost Mode; fallback не выдаёт локальное время активности.
- [ ] Чат: открыть из списка, открыть из подарка, открыть из профиля, закрыть, вернуться в список, повторить после перезапуска.
- [ ] Fake message: создать одну запись, повторно нажать Save, отредактировать, удалить, очистить чат; убедиться, что Postbox, journal и Stars ledger не расходятся.
- [ ] Fake gift/NFT: открыть action именно в чате, передать, проверить recipient profile, owner, fee, history и повторный запуск.
- [ ] Fake channel: owner/admin/member отображают разные права, строка ввода и edit controls видны только там, где это разрешено локальной моделью; сетевой запрос отсутствует.
- [ ] Profile overrides: username/tag, телефон и имя одинаково проецируются в профиле, заголовке, chat list и gift action.
- [ ] Stars: top-up, conversion, paid message, post/reaction и transfer дают одну идемпотентную запись в объединённой истории.
- [ ] Миграция: старые массивы читаются, неизвестная schema открывается read-only, повреждённый journal не возвращает удалённые записи.
- [ ] UI: настройки читаются как обычные категории, числа и даты валидируются, preview шрифта и подарка отражает выбранные значения.
- [ ] CI: локальные статические проверки, codec/store regressions и один полный IPA build после закрытия всех пунктов.

## Порядок работы

1. Закончить локальные модели и удобные редакторы каналов/профиля.
2. Стабилизировать чаты, CRUD и gift-проекции.
3. Свести Stars, транзакции, реакции и stats к одному проверяемому локальному источнику.
4. Довести Ghost Mode, медиа, voice changer и визуальные настройки.
5. Пройти повторную проверку из раздела выше, добавить только необходимые regressions.
6. Запустить один полный build, разобрать только финальный результат и приложить артефакты.
